Map who speaks for whom

What it is: The page, agent, user, and backend have different identities and authorities.

Why learn: Confusing these identities creates excessive delegation and authorization bugs.

Before modeling

Write the person’s request, the current state, and the evidence that will prove completion.

Starting error

Starting with a function name or a button produces a tool without a clear human goal.

Predict before opening the code

What information changes the decision? What effect needs to appear in the interface? Answer before implementing.

Use the same-origin policy

What it is: Origin combines scheme, host, and port and defines a central boundary of the Web.

Why learn: A tool registered by a document doesn’t grant unrestricted access to other origins.

Three different controls

exposedTo selects origins authorized to discover the tool; the Permissions Policy tools controls delegation in the document; the backend still authenticates the person and authorizes each effect.

Treat the iframe as a boundary

What it is: Embedded frames have their own document, origin, and lifecycle.

Why learn: The agent needs to know which context provides the tool and where its effect will be visible.

1

Observe

Capture state, input, and context before taking action.

2

Decide

Validate preconditions and choose the allowed transition.

3

Execute

Apply the shared rule and respect cancellation.

4

Prove

Update the interface and return a structured result.

Checkpoint

If step 2 fails, the tool doesn’t try to “make it work”: it returns an explicit recovery.

const tools = await document.modelContext.getTools({
  fromOrigins: ["https://agent.example"]

const selected = tools.find((tool) => tool.name === "buscar_cursos");

Don't turn CORS into authorization

What it is: CORS controls reading by browser scripts; the backend still validates identity and permission.

Why learn: A response allowed by CORS may still be forbidden for that user and operation.

REFERENCE CODE

fetch(api, { credentials: "include", signal });
// servidor valida sessão, escopo e CSRF

5

Request proportionate consent

What it is: Sensitive actions require clear confirmation that shows the target, effect, and reversibility.

Why learn: Generic or advance consent doesn’t cover a specific mutation.

Induced failure

Run the scenario with missing state, invalid input, or unavailable capability.

Expected recovery

The response explains what failed, what remains safe, and what action can continue.

Minimum test matrix

✓ reproducible happy path

✓ actionable invalid input

✓ cancellation ends the work

✓ fallback preserves the user journey

✓ interface reflects the state

✓ backend maintains authorization

confirm({ action: "cancelar inscrição", target: enrollmentId, reversible: false });

Test cross-context attacks

What it is: The suite covers tool spoofing, navigation during execution, a removed frame, and an unexpected origin response.

Why learn: Boundaries only truly exist when adversarial paths are exercised.

Synthesis exercise

  2. 2. Design the before and after states.
  3. 3. Implement the smallest functional proof.
  4. 4. Trigger a failure and record the recovery.
